# 队列调度说明

云网集群和深圳集群的 GPU 机器分成开发池和队列池。开发、调试用开发池。训练和批量推理用队列池，在华清云同一套页面里提交。本文说明两池为什么分开、怎么区别，以及两套环境共同的操作、排队规则、存储和网络差别。某种卡现在能不能提交、还剩多少张，以工作台里所选集群的当前页面为准。

深圳集群的机器范围、H800、代理变量和镜像地址见 [`sz-k8s-prod-queue-usage.md`](sz-k8s-prod-queue-usage.md)。

> **日期**：2026-10-28

## 先记住这几条

- 左侧进入「容器服务 → GPU 队列调度」。工作台看卡，任务页右上角「提交任务」。
- 下拉里云网是云网集群（标识 `yw-k8s`），深圳是 `sz-k8s-prod`。先选对集群，再选卡型。
- 不用填写队列名称，也不能自己提高优先级。用 `kubectl` 直接提交训练队列任务会被拒绝，原因是「队列任务只能通过华清云工作台提交」。
- 这种卡已经用满时仍然可以提交。任务会排队，不会马上失败。
- 蓝条「配额上限」是命名空间总配额。工作台「卡型额度」里标成「已生效」的一行，会再限制这一种卡。表是空的表示不按卡型再限，不是配额为 0。
- 云网可以把已有的共享盘挂到 Workspace，多副本一起读。深圳没有共享盘，要打开 Scratch，数据写到 `/scratch`。
- 云网的队列任务不注入 HTTP 代理。深圳的 H200 训练任务会自动带上代理。表单里都没有环境变量栏。
- 详情页「临时盘 / 副本」是容器可写层，两套集群都不能在表单里改。数据集和 checkpoint 不要只写在这里。

## 1. 开发池和队列池

交互开发要马上打开容器，改代码、看结果，不按任务顺序排队。训练和批量推理有明确的开始和结束，要按提交顺序、配额和空卡来排。两类工作若共用同一批机器，开发容器和训练会互相抢卡：训练可能等不到空卡，开发容器也没有排队位次可以说明它为什么还在等。所以每套集群把 GPU 机器分成两池：开发容器只使用开发池，工作台提交的训练和批量推理只使用队列池。

|  | 开发池 | 队列池 |
|---|---|---|
| 工作台卡片 | 开发池 · 开发机 | 队列池 · 训练推理 |
| 用来做什么 | SSH、Jupyter、单机调试。自己在容器里跑的推理服务也在这里 | 训练，以及该集群已经开放的批量推理 |
| 在哪里创建 | Helm、`kubectl`，或页面「创建容器」。工作台这张卡不能用来创建 | GPU 队列调度 → 任务 → 提交任务 |
| 会不会排队 | 不会。卡不够时容器一直等待机器，没有排队位次，也不出现在队列任务列表里 | 会。卡满或配额暂时不够时进入平台排队，等待中可以取消 |
| 已用怎么数 | 这些机器上已经调度上去的 GPU 申请，包括自己创建的开发容器 | 只数工作台里正在运行的训练和批量推理，不是这些机器上的实占 |
| 空闲后 | 云网的开发 Deployment 连续约 2 小时几乎不用 GPU，可能被缩容，见 [`gpu-idle-gc.md`](gpu-idle-gc.md) | 工作台训练任务不在这项回收里。任务结束或取消后释放卡 |

工作台最左边的「集群 GPU」已用，是开发池和队列池机器上已经调度上去的 GPU 申请。开发池已用用的是同一套实占。队列池已用不是实占，只数工作台里正在运行的训练和批量推理。两张卡的已用口径不同，加起来对不上集群已用。例如训练任务在页面上已经是运行中、容器还没落到节点时，队列池会计入，集群已用还没有；队列机器上有申请了 GPU、但不是这类运行中任务的容器时，集群会计入，队列池已用不计。

队列池里再按卡型和任务类型拆开。同一种卡的训练和批量推理是两条调度队列，在「调度队列」表里各占一行。训练队列满了，不表示推理队列也满；一种卡的队列满了，不挡另一种卡。不用自己填队列名称。上限是 0，或任务类型在页面上不能选，表示这条还没开放。没有开发队列。

开发容器不会落到队列池的机器上，工作台任务也不会落到开发池的机器上。不要在工作负载里写死 `spec.nodeName`。哪些机器属于哪一池、某种卡的训练或批量推理现在开没开，以该集群工作台的当前页面为准。深圳的队列机器和开发机器见 [`sz-k8s-prod-queue-usage.md`](sz-k8s-prod-queue-usage.md)、[`sz-k8s-prod-pod.md`](sz-k8s-prod-pod.md)。

### 有共享盘时，两池怎么交接同一份数据

开发容器和训练任务在不同的机器上。容器可写层、`/tmp`，以及只挂在某一台机器上的 Scratch（`local-path`），另一池都看不到。集群提供可多机同时挂载的共享盘时，两边挂同一块盘，才能把代码和数据交下去。

云网的共享存储类是 `h3c-csi-sc-nfs`，5090、H200、H20 都能挂。H200 还可以用 `h3c-csi-sc-epc`，5090 和 H20 不能挂 EPC。访问模式写 `ReadWriteMany`，状态要是 Bound。开发机和训练任务若不是同一卡型，用 NFS，不要用 EPC。深圳队列没有这种盘，开发机上的本地盘不能挂给训练任务，见 [`sz-k8s-prod-queue-usage.md`](sz-k8s-prod-queue-usage.md)。

盘要建在同一个命名空间里。开发容器把它挂到 `/workspace`。提交训练或批量推理时，在「存储与环境」里选进 Workspace，或作为追加 PVC。挂载路径写成同一个 `/workspace`。下拉里没有这块盘，是它还没 Bound，或访问模式不是 `ReadWriteMany`。

建议在这块盘上分开目录，不要把代码、数据和输出混在同一个文件里：

| 目录 | 谁来写 | 放什么 |
|---|---|---|
| `/workspace/code` | 开发容器 | 训练脚本和改过的代码 |
| `/workspace/data` | 开发容器准备好，训练任务读取 | 数据集、待验证的样本 |
| `/workspace/output` | 训练或批量推理任务 | checkpoint、日志、指标、导出结果 |
| `/workspace/debug` | 开发容器 | 从输出里抽出、用来核对的样本和记录 |

一轮常见顺序是：

1. 在开发池打开容器，把脚本写到 `/workspace/code`，把要用来训练或验证的数据放到 `/workspace/data`。
2. 提交队列任务，挂同一块盘。启动命令指向这个脚本，例如 `python /workspace/code/train.py`。checkpoint 和日志写到 `/workspace/output`。Scratch 只放这次任务的临时文件，开发机看不到。
3. 任务结束后，在开发容器里查看 `/workspace/output`，核对指标和样本。开发容器若已被缩容，这块共享盘还在；把副本数恢复后，仍能看到这些文件。
4. 需要改数据或脚本时，在开发容器里改 `/workspace/code` 和 `/workspace/data`。这次任务还在跑时，不要覆盖它正在读的脚本和数据；改动写成新文件，或等这次结束再改。
5. 再提交一条新任务，换一个任务名称，仍挂同一块盘，命令指向改过的脚本。输出写到新的子目录，例如 `/workspace/output/run-02`，避免盖掉上一轮的 checkpoint。

批量推理用同一块盘读 `/workspace/data`、把结果写到 `/workspace/output`。`helm uninstall` 会删除 Chart 新建的 workspace PVC，要保留数据时不要卸载后换一个名字重建。复用已有盘的写法见 [`gpu-workload-scenarios.md`](gpu-workload-scenarios.md)。

## 2. 工作台和任务列表

工作台顶部选集群，点「刷新」。三张卡的数字都是「已用 / 容量」：

| 卡片 | 用来看什么 |
|---|---|
| 集群 GPU | 这个集群已用卡数、容量，以及还剩多少张 |
| 开发池 · 开发机 | 开发容器用的卡。这里占满，不代表训练队列没有卡 |
| 队列池 · 训练推理 | 工作台训练和批量推理用的卡。提交前看这一格 |

「调度队列」表的列是：队列、卡型、任务类型、上限（卡）、运行任务、已用卡数、等待任务、等待卡数、状态。

| 状态 | 含义 |
|---|---|
| 空闲 | 已用卡数是 0 |
| 正常 | 已经有任务在用，还没到上限的 90% |
| 繁忙 | 已用卡数达到上限的 90% |
| 已满 | 已用卡数达到上限。仍可以提交，任务会排队 |
| 无卡 | 上限是 0，现在不能提交这种任务 |

等待任务是正在排队的任务条数。等待卡数是这些任务合计还要的卡数。两个都是 0，表示当前没有人在排队。队列正在跑任务时，等待卡数仍可以是 0。

再往下是「命名空间配额」，列是集群、命名空间、GPU（卡）。这一格把该命名空间各档配额的 GPU 数字加在一起，开发用的那一档不限制工作台训练。提交时以向导蓝条「配额上限」和提交后的说明为准。

「卡型额度」的列是命名空间、卡型、已用 / 上限、生效。已用是已经交到集群的卡，不含还在平台排队的卡。生效是「已生效」或「观察期」。表是空的时，原文是「未配置卡型额度（不按卡型限额，不等于 0）」：没有按卡型再设上限，配额不是 0。这一行由平台配置，提交页改不了。三道配额怎么一起生效，见第 4 节。

任务列表的列是：名称、命名空间、类型、GPU 卡型、状态、派发、GPU（卡）、用户、创建时间、操作。名称下面的小字是当前说明。

| 状态 | 含义 |
|---|---|
| 等待中 | 还没跑起来。名称旁可能有「平台排队」或「正在提交」 |
| 运行中 | 已经在机器上运行 |
| 已成功 | 进程正常结束 |
| 已失败 | 调度或运行失败。看名称下的说明，或打开详情里的状态流转 |
| 已超时 | 跑满了最长运行时间 |
| 已取消 | 已取消 |

| 派发 | 含义 |
|---|---|
| 平台排队 | 还没写入集群，可以取消。前面的任务或空卡满足后会自动再提交 |
| 正在提交 | 正在写入集群 |
| 已提交集群 | 已经交给集群。若仍是等待中，多半是在等一台机器装下 CPU、内存、临时盘或卡位 |

等待中或运行中的任务，操作列可以取消。

## 3. 提交向导

向导是「任务 → 算力 → 存储与环境 → 确认」。两套集群的字段相同。存储选哪一种、要不要代理，按第 8 节。

### 任务

| 字段 | 怎么填 | 过不了时的提示 |
|---|---|---|
| 集群 | 云网或 `sz-k8s-prod` | 请选择集群 |
| GPU 型号 | 该集群下拉里当前能选的卡型 | 请选择 GPU 型号。这种任务还没开放时，点下一步会提示当前不能提交 |
| 命名空间 | 自己的命名空间 | 请选择命名空间 |
| 任务类型 | 训练 `train`，或已开放的批量推理 `infer_batch` | 任务类型仅支持训练或批量推理 |
| 任务名称 | 例如 `train-demo-01` | 请填写任务名称。超过 63 个字符时提示「任务名称不能超过 63 个字符（DNS-1123）」。含大写、下划线或首尾是连字符时提示「任务名称须符合 Kubernetes DNS-1123：小写字母/数字/连字符，且以字母或数字开头和结尾」 |
| 选择镜像 | 该集群镜像仓库里的项目和版本，或自定义地址 | 请选择镜像或填写自定义镜像地址 |
| 启动命令 | 可留空。要填就写成 JSON 字符串数组 | 见下面 |

启动命令示例：

```json
["python","/app/train.py","--epochs","100"]
```

留空表示使用镜像自己的入口。填写时整段必须是 JSON 数组，每一项都是字符串。页面会拒绝这些写法：

- 不是 JSON 数组：提示「启动命令必须是 JSON 数组格式」，或「启动命令格式错误，请输入有效的 JSON 数组」。
- 写成 `[]`：提示「启动命令数组不能为空」。
- 数组里有数字或对象：提示「启动命令数组的每个元素必须是字符串」。

### 算力

顶部蓝条形如：

```text
单任务上限：GPU … · CPU … · 内存 … | 配额上限：GPU … · CPU … · 内存 …
```

数字以你打开页面时的蓝条为准。云网和深圳、不同命名空间，这两组数字都不同。

| 蓝条 | 按什么比 | 超过时 |
|---|---|---|
| 单任务上限 | 每一个副本。GPU、CPU、内存都不能超过一台队列机器装得下的上限 | 「每副本 GPU … 超过单任务上限 …」，或 CPU、内存的同样提示。汇总时也可能是「超过单任务上限」 |
| 配额上限 | 整次任务的命名空间总配额。GPU 按「每副本卡数 × 副本数」与这一档比，CPU、内存同样比 | 「超过命名空间配额上限」。提交时也可能写成「GPU：本次申请 … 超过命名空间配额上限 …」 |

蓝条不包含卡型额度和训练分档。队列里还有空卡，只要合计超过蓝条里的总配额，这一步就过不去。总配额暂时不够、但这一条任务本身没超过上限时，可以提交成功并进入平台排队。卡型额度、训练分档更严时，向导仍可能让你走到提交，再按第 4 节拒绝或排队。

| 字段 | 预填 | 要求 |
|---|---|---|
| GPU / 副本 | 1 | 正整数，且不超过蓝条里的单任务上限 |
| CPU（核） | 1 | 正数核，或 millicpu。`0.5`、`2`、`500m` 可以。提示「CPU 须为正数核数或 millicpu（例如 0.5、2、500m）」 |
| 内存 | 2 Gi | 正整数 Gi。提示「请填写内存（正整数 Gi）」 |
| 共享内存 shm | 开，1 Gi | 默认开启。计入内存配额，且不得超过本任务内存。提示「shm 不得超过 memory」或「请填写共享内存 shm（正整数 Gi）」 |
| 副本数 | 1 | 正整数。大于 1 时不能启用 scratch |
| 最长运行（天） | 3 | 正整数。提示「最长运行天数须为正整数」。超过 30 天提交会被拒绝。训练不改这一栏时，平台默认最长约 7 天；批量推理约 1 天 |
| 最少就绪副本数 | 与副本数相同 | 正整数，且不能超过副本数。提示「最少就绪副本数须为正整数，且不能超过副本数」。这些副本要一起就绪后才开始跑 |

### 存储与环境

这一页两套集群都能看到 Workspace、追加 PVC、Scratch 和 EGL。选法不同，见第 8 节。共同限制：

- Scratch 默认关闭。打开后挂载路径固定 `/scratch`，容量是正整数 Gi，不能超过页面写出的集群上限。提示「请填写 scratch 容量（正整数 Gi）」或「scratch 容量不能超过集群上限 …Gi」。
- 副本数大于 1 时开关是灰的，提示「副本数大于 1 时不能启用 scratch（RWO 本地盘，无法多副本共享）」。
- 「复用已有」会回到这块盘第一次调度到的那台机器。两份任务同时挂同一块盘时，后提交的会一直等待。下拉里没有的盘，是还在被占用，或已经绑在另一种卡的机器上。
- 详情页「临时盘 / 副本」是容器可写层，创建表单里没有这一栏。任务删除后，写在 `/`、`/tmp` 和镜像目录里的文件会消失。
- 图形附件「启用 EGL」训练时保持关闭。
- 路径没成对、重复，或占用了 `/scratch`，页面会提示「追加挂载的 PVC 与路径必须成对填写」「挂载路径不能重复」「路径 /scratch 为系统保留」。

### 确认和详情

确认页核对集群、卡型、命名空间、类型、名称、镜像、命令、资源、shm、天数，以及 Workspace、Scratch、EGL，再点「提交」。

详情页从上到下是：资源申请（含临时盘 / 副本）、PVC 挂载、运行与归属、镜像、状态流转、容器日志。排队时间不计入已运行时间。还在平台排队时，容器日志是空的。等待中或运行中可以「取消任务」。要按同样参数再交一条，用「复制为新建任务」。

## 4. 什么情况下会直接被拒绝

下面这些情况，这一条任务按当前申请永远调度不了，工作台会拒绝，而不是放进排队：

- 这种卡的训练或批量推理还没有开放。
- 本任务合计卡数超过该队列能接收的上限。合计卡数按「每个副本的卡数 × 副本数」计算。
- 单个副本要的 GPU、CPU、内存或临时盘，超过一台可调度机器能装下的上限。
- 本任务自己的卡数、CPU 或内存已经超过命名空间总配额。提示里会有「申请合计 … 超过命名空间总上限 …」，或向导里的「超过命名空间配额上限」。
- 训练任务自己的卡数已经超过训练分档。提示是「申请合计 N 卡超过训练分档上限 M 卡」。批量推理不看这一档。
- 这种卡的卡型额度已经生效，而且本任务合计卡数超过那一行上限。提示是「申请合计 N 卡超过命名空间 … 卡型上限 M 卡」。上限是 0 时，提示是「命名空间未获准使用 … 卡型（额度为 0 卡）」。观察期不按这行拒绝。

页面会给出原因。请减小申请、换卡型，或联系平台管理员调整配额。不要原样反复提交。

## 5. 提交成功之后

| 页面上的情况 | 含义 | 建议 |
|--------------|------|------|
| 开始调度 | 空卡够用，而且没有更早、此刻也放得下的任务挡在前面 | 等待任务跑起来 |
| 平台排队，可以取消 | 命名空间配额暂时不够，或这种卡现在用满，或有更早且放得下的任务还在等 | 保留这一条，等它自动再调度。看说明区分是配额还是卡满 |
| 已经提交，仍在等一台机器 | 账面上的卡够，但这台机器的 CPU、内存、临时盘或卡位暂时被占着 | 继续等。不要取消后再原样新建一条 |

排队期间任务还没有分到 GPU。取消排队中的任务即可释放这个位次。

说明原文用来区分原因。数字会随任务变化。

| 页面说明 | 含义 |
|----------|------|
| `命名空间总配额不足：已占用 X 卡 + 前序排队 Y 卡 + 本任务 Z 卡 > 上限 N 卡；进入平台排队，前序任务完成后自动调度` | 这条任务本身没有超过总配额，加上已经占用的和排在前面的才超过。前面各种卡的任务都算。前面的任务结束后会自动再调度 |
| `训练 分档配额不足：已占用 X 卡 + 前序排队 Y 卡 + 本任务 Z 卡 > 上限 N 卡；进入平台排队，前序任务完成后自动调度` | 总配额还够，训练这一档暂时不够。只统计训练任务。批量推理不会因为这一档排队 |
| `H200 卡型额度不足：已占用 X 卡 + 前序排队 Y 卡 + 本任务 Z 卡 > 上限 N 卡；进入平台排队，前序任务完成后自动调度` | 卡型名称按你选的型号。只统计这一种卡。别的卡型占用不占这一行，但会计入上面的总配额 |
| `调度队列 … 当前卡已用满（队列占用 a/b，产品池空闲 c 卡），本任务 d 卡需排队等待资源；有空闲卡且本任务放得下时自动提交` | 这种卡现在用满了。说明里的「产品池」指当前用来跑这种训练或批量推理的机器。有空卡并且本任务放得下时会自动提交 |
| `调度队列 … 有更早提交的任务正在排队，本任务 d 卡需等待前序任务；当前空卡由更早且放得下的任务优先占用` | 空卡够本任务用，但有更早提交、而且此刻也放得下的任务优先 |
| `目标节点暂时装不下本任务（CPU/内存/临时盘或单机卡位被占用），等待资源释放后自动落到节点` | 卡数账面上够。等机器腾出 CPU、内存、临时盘或卡位 |

「配额不够」和「卡已用满」是两件事。配额又分成总配额、训练分档和卡型额度，说明里写的是哪一句，就是卡在哪一道。只加总配额解决不了卡型额度或卡满；只等别人释放卡，也解决不了自己的配额不够。

## 6. 位次和等待失败

位次按提交时间编号。双方都放得下时，更早提交的先占用空卡。前面的任务因为自己的配额不够而排队时，不会挡住别人。不同卡型的空卡互不影响。卡型额度的前序排队也只算同一种卡。命名空间总配额的前序排队则把这个命名空间里更早的任务都算上。

举例：前面的任务要 4 张卡，现在只空出 2 张。后面只要 2 张的任务可以先跑，前面的任务继续等 4 张同时空出来。

卡已经用满，或单台机器暂时装不下，不会在大约 15 分钟后被标成失败。排队期间也不计这 15 分钟。申请超过单机上限，或这种卡当前没有可调度的机器，等待超过大约 15 分钟会失败，说明里写「调度超时」。页面上的等待时间以说明原文为准。镜像拉不下来不属于这种失败。任务已经落到机器上、镜像却一直拉不下来时，卡仍然占着，要取消任务或改镜像。

跑满任务时限之后结束，是运行时间到了，不是排队超时。

## 7. 卡数和副本

- 配额和队列占用都按「每个副本的卡数 × 副本数」计算。
- 多个副本默认要一起启动。凑不齐就不会先跑其中一部分。
- 单个副本必须能放进一台机器。副本数大于 1 时，合计卡数可以多于一台机器的卡数，但每个副本都不能超过单机上限。
- 临时盘不用自己填，平台按可调度机器的容量填写。

## 8. 云网和深圳的差别

页面步骤相同。提交前先对一下集群，存储和网络按这一表选。

| 项 | 云网集群 `yw-k8s` | 深圳集群 `sz-k8s-prod` |
|---|---|---|
| 共享数据盘 | 已有、并且是 Bound + 可多机同时挂载的盘，可以选进 Workspace 或追加 PVC。云网共享存储类是 `h3c-csi-sc-nfs`；H200 还可以用 `h3c-csi-sc-epc`。访问模式用 `ReadWriteMany` 之后，才会出现在这个下拉里 | 没有这种共享盘。Workspace 保持「不挂载工作目录」，不要追加 PVC |
| Scratch | 单机本地盘，存储类 `local-path`，路径 `/scratch`。多副本任务不要开，数据改放 Workspace | 队列任务的数据盘就是这块。打开「启用 scratch」，来源选「新建」，副本数保持 1 |
| 多副本 | 数据放共享 Workspace。Scratch 保持关闭 | 这次不做多机。一张队列机器最多 8 张卡，细节见深圳文档 |
| 容器可写层 | 详情页「临时盘 / 副本」，不要当数据盘 | 同样不能当数据盘。2026-10-26 一张 1 卡任务是 48Gi，以该任务详情为准 |
| 出网 | 队列任务不注入 HTTP 代理，容器走节点原有网络 | H200 训练任务自动注入 `http://33.1.42.5:8888`。变量全文见 [`sz-k8s-prod-queue-usage.md`](sz-k8s-prod-queue-usage.md) |
| 镜像仓库 | `https://harbor.xa.hqzyai.com:19443/`，见 [`harbor-images.md`](harbor-images.md) | `https://harbor.sz-prod.hqzyai.com:8443/`。不要从云网仓现场拉十几 GB |
| 当前能提交的卡 | 以该集群工作台的 GPU 型号和任务类型为准 | 现在是 H200 训练。H800 和批量推理不能提交 |

开发容器若连续约 2 小时几乎不用 GPU，可能被平台缩容，规则见 [`gpu-idle-gc.md`](gpu-idle-gc.md)。该文写的是云网集群。工作台提交的训练任务不在这项回收里。两池的区别见第 1 节。

## 9. 常见问题

### 训练任务为什么看不到开发机里改的代码？

开发容器和训练任务不在同一台机器上。只写在容器里、`/tmp` 或某一台机器的 Scratch 上的文件，另一边看不到。集群有共享盘时，两边挂同一块 `ReadWriteMany` 的盘，路径都用 `/workspace`，代码、数据和输出按第 1 节的目录分开。深圳队列没有这种盘。

### 页面上这种卡还有剩余，为什么不能提交训练？

剩余卡若在开发池，不能用来提交训练。训练只使用队列池里当前开放的机器。这种卡的训练还没开放，或当前没有可调度的训练机器时，工作台会拒绝，并写明原因。

### 卡已经用满，提交会不会马上失败？

不会。提交会被接受并进入排队，说明里会写「卡已用满」。有空卡并且本任务放得下时自动提交。不要取消后立刻再建一条相同的任务。

### 我排在前面，为什么后面的任务先开始了？

位次是提交顺序。前面的任务要 4 张、现在只空 2 张时，后面要 2 张的任务可以先跑。前面的人若是自己的配额不够，也不会挡住别人。

### 排队很久会不会自己失败？

卡用满或单机暂时装不下，不会因此失败。申请超过单机上限，或这种卡没有可调度机器时，等待超过大约 15 分钟会失败，说明里会写「调度超时」，并提示减小申请或联系平台管理员。

### 能不能指定队列，或提高优先级先跑？

不能。队列由平台按卡型和任务类型对应，优先级也不能在提交时修改。

### 开发池满了，还能提交训练吗？

能。开发池是开发容器用的卡。训练看队列池和调度队列的已用卡数。队列满了可以提交，任务进入平台排队。

### Workspace 下拉是空的，要不要管？

云网：下拉里出现的是已经绑定、而且能多机同时挂载的共享盘。空着表示这个命名空间里还没有这样的盘。多副本任务需要先有一块 `ReadWriteMany` 的共享盘，再回到这里选择。单机任务可以改开 Scratch。

深圳：队列侧没有共享盘，下拉会是空的。保持不挂载，打开 Scratch。见 [`sz-k8s-prod-queue-usage.md`](sz-k8s-prod-queue-usage.md)。

### 为什么有的任务要代理，有的不用？

云网队列任务不注入代理。深圳 H200 的工作台训练任务会自动带上代理。自己创建的开发容器在两套集群里都不会自动带上队列任务的这组变量。深圳开发容器的写法见 [`sz-k8s-prod-h200-network.md`](sz-k8s-prod-h200-network.md)。

### 「空闲」和「等待卡数 0」分别是什么意思？

已用卡数是 0 时，状态是「空闲」。已经有人在用、还没到很满时，状态是「正常」。等待卡数是 0 表示当前没有任务在排队等卡。

### 卡型额度和蓝条里的配额上限有什么区别？

蓝条「配额上限」是这个命名空间的总配额，各种卡加在一起算，向导会按它拦截。卡型额度只限制你选的那一种卡，而且只在「已生效」时才拦。

| 工作台上的样子 | 提交时 |
|---|---|
| 「卡型额度」是空表，原文「未配置卡型额度（不按卡型限额，不等于 0）」 | 不按卡型再限。仍受总配额、训练分档和队列上限约束 |
| 某一行是「已生效」，上限大于 0 | 这一条合计卡数超过该上限，直接拒绝，提示「申请合计 N 卡超过命名空间 … 卡型上限 M 卡」。没超过上限、但已占用加前序排队再加本任务超过了，会进入平台排队 |
| 某一行是「已生效」，上限是 0 | 这个命名空间不能用这种卡。提示「命名空间未获准使用 … 卡型（额度为 0 卡）」。队列里有空卡也提交不了 |
| 某一行是「观察期」 | 这一行先不拦。仍按总配额和训练分档 |

表上的「已用 / 上限」不含还在平台排队的卡。所以已用没到上限，新任务仍可能因为前序排队而进平台排队。说明里会写「… 卡型额度不足：已占用 X 卡 + 前序排队 Y 卡 + 本任务 Z 卡 > 上限 N 卡；进入平台排队，前序任务完成后自动调度」。

举例：总配额 8 张，H200 卡型额度已生效且上限 4 张。这一条要 6 张 H200 时，蓝条可能让你通过，提交会被拒绝。这一条只要 2 张、而这种卡已经占用 3 张时，任务会排队，不会马上失败。

### 总配额还够，为什么训练进了排队或被拒绝？

训练还有一道分档，可能比总配额更小。蓝条不单列这一档。这一条自己就超过时，提交失败，提示「申请合计 N 卡超过训练分档上限 M 卡」。自己没超过、加上已有训练和更早的训练任务才超过时，进入排队，说明是「训练 分档配额不足：已占用 X 卡 + 前序排队 Y 卡 + 本任务 Z 卡 > 上限 N 卡；进入平台排队，前序任务完成后自动调度」。批量推理不看这一档。

### 为什么提示任务名已存在？

同一个命名空间里，未结束的任务不能同名。取消或结束后再交一条同名任务，若集群里还留着同名对象，也会被拒绝。提示是「任务名 … 已存在（状态 …），请更换名称」，或「集群中已存在同名任务 …，请更换名称或先删除该任务」。用「复制为新建任务」时请改一个名称。
